# Sound

Every sound this game makes is generated by `tools/generate-game-sounds.py` and
committed as a 16-bit mono WAV under `frontend/assets/sounds/<pack>/`. Nothing
here was recorded, bought, or downloaded. The tool depends on nothing but the
Python standard library, so the whole set can be rebuilt from a clean checkout:

```
python3 tools/generate-game-sounds.py
```

That run rewrites all thirty-six clips and the waveform module the picker draws
from. It is deterministic — the same checkout produces byte-identical files —
so a rebuild that changes a file means someone changed the tool.

## Why they are generated

This repo has to satisfy three things at once: it is GPL-3.0, the App Store
build is proprietary, and the game may be monetised. That combination rules out
every copyleft asset licence and every non-commercial one, and a CLA does not
help because it binds contributors to this repo, not the author of a sound
somebody downloaded.

It has already cost us once. The set that shipped first was scraped from
Chess.com — nine files whose *names* were enough to identify them — and it
blocked the open-source release outright until it was replaced. Lichess is not
an escape hatch: the standard set whose filenames match is listed under
"Exceptions (non-free)" in its `COPYING.md`, and its freely-licensed sets are
AGPLv3+ or CC BY-NC-SA, which fail the App Store build and the monetisation test
respectively.

So the rule for this directory is: **self-generated, or verified CC0, and
nothing else.** Self-generated is strictly better — there is no attribution to
carry and no obligation to track. The same test applies to the piece artwork.

## Loudness, and why the old set was unpleasant

The previous generator normalised each clip to a fixed *peak*. Peak is not
loudness: a dry sine and a burst of filtered noise at the same peak are nowhere
near equally loud, and a clip's peak says nothing about how long it holds. The
set that produced had no relationship between what a sound meant and how loud it
was, measured across the whole of it:

| | old | now |
|---|---|---|
| a move | −25.2 | −28.0 |
| a refused move | **−10.4** | −27.0 |
| a game ending | −11.9 | −21.5 |
| spread across the set | 14.7 dB | 6.5 dB |

A refused move — a misclick, the most trivial thing that can happen — was the
loudest sound in the game, fifteen decibels above the move sound it interrupted.
That single row is most of what "the sounds are loud and bad" meant.

Every clip is now normalised to a target on a perceptual scale instead:
BS.1770 K-weighting, measured over the loudest 100 ms of the clip rather than
integrated across it. Integrated loudness is the wrong tool for a one-shot — its
gating discards blocks below a threshold, so a 90 ms click measures as whatever
silence happens to surround it — and 100 ms is near enough the ear's own
integration time that two clips matched this way sound matched.

The ladder lives in `EVENT_LOUDNESS` and is meant to be read as a ranking:

```
move (yours)        −28.0     the one that fires every ply, so the quietest
move (theirs)       −27.5
refused move        −27.0     a slip, not an offence
captures            −24.5 … −24.0
game starts         −22.5
notification        −22.0
game ends           −21.5
```

Broadcast speech sits at −23 LUFS, for scale. The whole set is deliberately
under it: these are punctuation, not content.

The metering in the tool was checked against `ffmpeg`'s BS.1770 implementation
on steady tones from 60 Hz to 12 kHz and agrees within 0.04 dB.

## Packs

A pack is a `Voice`: a description of what a piece landing on this board is
*made of*. The nine events are then composed from that voice by shared code, so
a pack is cohesive by construction — a game ending is the same material as a
move, struck harder and left to ring — and there is no set of nine hand-written
clips to keep in agreement.

| Pack | Voice |
|---|---|
| Wood | Inharmonic struck body, fast decay, filtered transient. The default. |
| Felt | The same idea damped: slow attack, dark, and 5 dB under the ladder. |
| Arcade | Pulse waves with a pitch bend, low-passed to kill the aliasing. |
| Glass | Stretched bell partials on a pentatonic, left to ring. |
| Silent | A pack whose every clip is `null`. |

Silent is a pack rather than a flag, which is what keeps it out of every branch
in the sound layer: `null` is a legal source in expo-audio, so a player with
nothing to play makes no sound and nobody has to remember to check a mute
setting.

## Adding a pack

1. Add a `Voice` to `VOICES` in the generator and run it. Check the report: a
   clip that lands more than 0.6 dB off its target is flagged, and the tool
   prints every level.
2. Add the pack to `SOUND_PACKS` in `frontend/src/appearance/soundPacks.ts`,
   with all nine `require` paths spelled out in full. Metro resolves `require`
   by reading the literal, so an interpolated path bundles nothing — it works on
   the web dev server and plays silence on a phone.
3. Run `frontend`'s tests. `catalogue.test.mts` checks that every path exists on
   disk, that a pack plays its own clips and not another pack's, and that it has
   a waveform for the picker.

Do not edit a WAV under `frontend/assets/sounds/` by hand. The next run of the
tool will overwrite it, and the file will disagree with the code that claims to
describe it in the meantime. Change the voice.

## The picker

Appearance draws each pack as the envelope of that pack's own move clip — the
clip choosing it plays back. The data is in
`frontend/src/appearance/soundWaveforms.ts`, written by the generator from the
rendered audio, so the picture cannot drift from the sound.

Both axes are shared across the packs on purpose. A per-clip time axis would
draw Glass and Felt the same width when one rings six times longer than the
other, and a per-clip amplitude would draw Felt at full height when the whole
point of Felt is that it is quieter.

## Playback

`frontend/src/hooks/useGameSounds.tsx` owns which event fires when, and carries
the two platform problems worth knowing about: browsers grant permission to make
a sound per `<audio>` element and only inside a gesture, which is why a pack
change primes every clip immediately rather than waiting; and both mobile
platforms assume an app making a sound wants the stage to itself, which is why
the audio session is set to mix rather than interrupt. Both are commented where
they live.
